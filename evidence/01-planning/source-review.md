Reviewed the supplied COIT13236 assessment specifications, marking rubric,
individual option documents, technical artefact plan, updated project plan and
the supplied 12-file repository snapshot. The two pasted implementation
specifications have identical SHA-256 hashes. The user explicitly selected SITAS

## Assessment findings

- Assessment 2 comprises two individual progress reports, each worth 12.5%, due
  Monday of weeks 6 and 9. Exact calendar dates and times require Moodle.
- The marking rubric allocates 7 marks to individual contribution, 6 to project
  progress, 6 to reflection/accountability and 6 to engagement/conduct.
- Each report must show specific verifiable evidence, realistic completion
  percentages, an itemised contribution record and a remaining-work plan.
- Supporting evidence must be embedded in a single submission document. A live
  demonstration is compulsory in the submission week's mentor meeting.
- Contributions must map to responsibilities in the approved proposal. The
  approved proposal was not included in the supplied materials; approval and
  responsibility changes cannot be established from the supplied plans.
- AI collaboration is allowed with critical evaluation and modification and an
  accurate account of tools, method and extent. The assessment acknowledgement
  is maintained separately in the student's private assessment material.

Sources: Assessment 2 Specifications pages 1-3; Assessment 2 Marking Rubric pages
1-3; Assessment 1 Description pages 1-6. These are supplied-file findings, not a
claim that current Moodle information was checked.

## Project observations

The plans describe fictional care staff, shared workstations, authenticated
applications and protected fictional resident information. They support offline
identity threat modelling as an individual technical workstream. Prior option
documents are planning proposals, not implementation evidence.

The supplied repository ZIP is a partial source snapshot. It lacks a README,
dependency manifest, architecture document and executed test evidence. A
truncated PowerShell file prevents treating the snapshot as a fully working
system. No archive scripts were executed and no archive code or configuration
was imported into SITAS.

## Decisions

Use Python's standard library for the runtime and JSON for synthetic inputs.
Use iterative depth-first search to enumerate bounded simple directed paths.
Define explicit educational risk and control semantics before implementation.
Maintain requirements, tests, reports and evidence separately. Describe the
application's own offline scope in public documentation, following the user's
clarification. Do not claim live-tenant validation, attendance, proposal approval
or student demonstration based on generated artefacts.
