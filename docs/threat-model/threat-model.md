# SITAS threat model

SITAS models hypothetical identity compromise in a fictional care environment. Its purpose is to explain how credentials, identities, devices, sessions, applications and privileges can connect an attacker to a protected asset, and which simulated control rules change those paths.

## Security objectives

The model focuses on confidentiality of fictional resident information, protection of workforce data, and integrity of identity-administration capabilities. Each protected target has an explicit impact value. Paths represent assumed opportunities to reach that target; the simulator evaluates reachability and relative exposure within those assumptions.

## Environment and trust transitions

The synthetic environment includes workforce and agency identities, a former-worker identity, shared workstations, a care portal, an administration console, credentials, sessions, roles and protected assets. A directed edge records one transition and why the transition is possible in the scenario.

Relevant transitions include an attacker obtaining a credential, using it to authenticate, acquiring an existing session, using a shared device, accessing an application, obtaining an inappropriate privilege and reaching protected information or administration. Authentication, session access, application access and privileged operations represent distinct security decisions in the model.

The edge sequence is an attack-state abstraction. It is not a packet trace or an instruction to exploit a running system. A node's appearance later in a path means the modeled transition makes that state or capability reachable.

## Assumptions and preconditions

A scenario declares its source, protected target and allowed edge set. Selecting an edge asserts that its described preconditions are present for that scenario. Distinct paths may share a credential, application or final asset. Parallel edges can describe different mechanisms between the same nodes, such as password-only authentication and an MFA social-engineering route.

Conditions are explicit labels and attributes. The engine does not infer weakness from a person's name, discover live configuration, or execute script text supplied in a model. An unmodeled path cannot be discovered.

## Threats and simulated defences

| Threat condition | Modeled effect | Relevant simulated control |
| --- | --- | --- |
| Stolen workforce password | Authentication transition becomes reachable | MFA |
| Active session left on a shared workstation | Another actor can reach the session | Timeout, individual accounts, device/session separation |
| Former-worker credential still accepted | Residual authentication path exists | Targeted account disablement |
| Overbroad access relationship | Standard identity can reach a restricted operation | RBAC and least privilege |
| Administrative credential compromised | Privileged operation reaches a critical target | Administrative restriction, privileged reauthentication |
| Social-engineering route past MFA | An alternative authentication transition survives | Explicit likelihood cap on the bypass route |
| Session token acquired | Existing session reaches an application without a new password step | Session revocation and device/session separation |
| Compromised agency credential | Credential and shared-device path exposes data | MFA, individual accounts and least privilege |

Each control affects only edges matched by its explicit rules. A password-oriented MFA rule does not automatically protect an already established session. Timeout should distinguish a stale session from a fresh one. Account disablement should address a selected simulated identity, with its scope visible in the result.

## Analysis method

Iterative DFS enumerates simple source-to-target paths within a declared maximum edge depth. The minimum edge likelihood is combined with target impact to form an ordinal risk indicator. Controls block or cap matched transitions; the engine then enumerates the controlled graph again. Comparison retains blocked baseline paths and explains whether surviving paths have a lower or unchanged score.

The scenario catalogue supplies ten teaching cases. Counts and scores must be generated by execution, and analysis is complete only within the selected model and bounds. [Assumptions and limitations](../limitations/assumptions-and-limitations.md) records the interpretation limits.
